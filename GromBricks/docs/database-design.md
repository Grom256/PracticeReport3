# Структура бази даних GromBricks

Ця схема відтворює початкову ER-діаграму магазину, але пристосована до Django ORM. Джерелом структури п'яти таблиць магазину є `database/create_schema.sql`; моделі Django мають відповідати цьому SQL-коду. Службові таблиці Django для користувачів, прав, сесій і Admin створюються вбудованими Django migrations.

## Таблиці магазину

### `auth_user` — облікові записи

Таблицю використовує стандартна система автентифікації Django. Тут зберігаються логін, ім'я, прізвище, email, хеш пароля, дата реєстрації та ознаки доступу. Пароль у відкритому вигляді не зберігається. Службові таблиці Django для груп, дозволів і сесій створюються вбудованими Django migrations.

### `catalog_category` — категорії

| Поле | Призначення |
| --- | --- |
| `id` | Первинний ключ, створений Django |
| `name` | Назва категорії, унікальна |
| `slug` | Унікальна частина URL |
| `description` | Опис, необов'язковий |
| `is_active` | Чи показувати категорію |

### `catalog_product` — товари

Одна таблиця для мініфігурок і окремих деталей; тип задає поле `product_type`.

| Поле | Призначення |
| --- | --- |
| `id` | Первинний ключ |
| `category_id` | Зовнішній ключ на `catalog_category.id` |
| `owner_id` | Зовнішній ключ на `auth_user.id`; користувач, який створив запис товару |
| `product_type` | `minifigure` або `part` |
| `sku` | Унікальний артикул |
| `name`, `description` | Назва й опис |
| `series`, `color` | Тематика й колір, необов'язкові |
| `condition` | Стан: новий або вживаний |
| `price` | Ціна `DECIMAL(10,2)`, не від'ємна |
| `stock_quantity` | Залишок на складі |
| `image` | Шлях до одного зображення, може бути порожнім |
| `is_rare`, `is_active` | Ознаки рідкісного товару й видимості в каталозі |
| `created_at`, `updated_at` | Дата створення й останнього оновлення |

### `orders_order` — замовлення

| Поле | Призначення |
| --- | --- |
| `id` | Первинний ключ |
| `user_id` | Зовнішній ключ на `auth_user.id`; може бути `NULL`, якщо обліковий запис видалили |
| `recipient_name`, `phone` | Дані одержувача |
| `city`, `address`, `postal_code` | Адреса або відділення доставки |
| `delivery_service` | Укрпошта, Нова пошта або Meest |
| `payment_method` | Накладений платіж при отриманні; платіжного сервісу немає |
| `status` | Стан замовлення |
| `created_at`, `updated_at` | Дати створення й оновлення |

Сума замовлення обчислюється з його позицій. Це не дубльована колонка, яка могла б розійтися з фактичним складом замовлення.

### `orders_orderitem` — позиції замовлення

| Поле | Призначення |
| --- | --- |
| `id` | Первинний ключ |
| `order_id` | Зовнішній ключ на `orders_order.id` |
| `product_id` | Зовнішній ключ на `catalog_product.id` |
| `quantity` | Кількість товару, має бути більшою за нуль |
| `unit_price` | Ціна одиниці на момент покупки, не від'ємна |

Пара `order_id` + `product_id` унікальна: один товар у межах одного замовлення зберігається одним рядком із відповідною кількістю.

## Зв'язки та збереження історії

- Одна категорія має багато товарів; видалити категорію з товарами не можна (`PROTECT`).
- Один staff-користувач може мати багато створених товарів; при видаленні користувача товар лишається, а `owner_id` стає `NULL` (`SET NULL`).
- Один користувач може мати багато замовлень; при видаленні користувача замовлення зберігаються, а `user_id` стає `NULL` (`SET NULL`).
- Одне замовлення має багато позицій; видалення замовлення видаляє його позиції (`CASCADE`).
- Один товар може входити до багатьох позицій замовлень; товар із замовленнями не видаляється фізично (`PROTECT`), його слід деактивувати.

## Створення таблиць

Проєкт використовує MySQL Server 8.4. Спершу `database/reset_database.sql` створює порожню базу `grombrick`, потім Django migrations для `auth`, `admin` і `sessions` створюють службові таблиці, а `database/create_schema.sql` створює п'ять таблиць магазину. Запускай SQL-скрипти у MySQL Workbench або MySQL CLI до `createsuperuser` і запуску сервера. Не запускай `python manage.py migrate` без назви службового застосунку. Облікові дані беруться з локального `.env`, який не додається до Git; назви змінних наведені у `.env`.
