# GromBricks

Навчальний інтернет-магазин LEGO-мініфігурок і окремих деталей на Django та MySQL.

Таблиці магазину створюються SQL-скриптом `database/create_schema.sql`. Django migrations використовуються лише для службових таблиць Django: користувачів, прав, сесій і Admin.

## Локальний запуск

Потрібні Python і MySQL Server 8.4. Скрипт `database/reset_database.sql` видаляє базу `grombrick` і створює порожню заново. Скрипт `database/create_schema.sql` створює таблиці магазину, після чого додає початковий товар. Дані у відповідних таблицях будуть втрачені.

З кореня репозиторію скопіюйте приклад налаштувань і заповніть `.env` своїми параметрами MySQL. Не додавайте `.env` до Git:

```powershell
Copy-Item GromBricks\.env.example GromBricks\.env
```

Потім виконайте:

```powershell
cd GromBricks
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
Get-Content database\reset_database.sql | mysql -u root -p
..\.venv\Scripts\python.exe manage.py migrate auth
..\.venv\Scripts\python.exe manage.py migrate admin
..\.venv\Scripts\python.exe manage.py migrate sessions
Get-Content database\create_schema.sql | mysql -u root -p
..\.venv\Scripts\python.exe manage.py createsuperuser
..\.venv\Scripts\python.exe manage.py runserver
```

У `.env` значення `MYSQL_DATABASE` має бути `grombrick`, якщо SQL-скрипти не були вручну адаптовані під іншу назву бази. Не запускайте `manage.py migrate` без назви застосунку, інакше Django застосує також старі міграції таблиць магазину. Django Admin відкривається за адресою `/admin/`. Назви змінних оточення наведені в `.env`; секретні значення зберігай лише у локальному `.env`.

## Зміна структури даних

Для нового поля, таблиці, індексу чи обмеження онови модель Django та `database/create_schema.sql` в одному наборі змін. Міграції, що залишилися в `apps/*/migrations/`, зберігаються як історія розробки та не використовуються для побудови таблиць магазину.

## Структура даних

- `Category` — тематичні категорії товарів, наприклад серії LEGO.
- `Product` — мініфігурки й деталі з ціною, станом, залишком та ознакою рідкісного товару.
- `Order` — покупець, адреса, служба доставки, спосіб оплати, статус, сума товарів, автоматична знижка та фінальна сума до оплати.
- `OrderItem` — склад замовлення з ціною товару на момент покупки.
- `WishlistItem` — список бажань користувача (товари в наявності та без залишку).
- `StockNotification` — підписки на сповіщення про появу товарів на складі через Email та/або Telegram (@GromBricksBot).
- Реалізовані реєстрація, вхід/вихід і редагування базових даних профілю (включно з Telegram Chat ID) через стандартну автентифікацію Django.
- Кошик авторизованого користувача зберігається в сесії; підтримує автоматичні знижки (сума > 2500 грн — 5%, сума > 5000 грн — 10%).
- Сповіщення про наявність товару: коли менеджер поповнює залишок товару (`stock_quantity > 0`), система автоматично надсилає сповіщення підписникам на Email та в Telegram.
- Оформлення замовлення створює запис із позиціями та цінами на момент покупки, фіксує отриману знижку, перевіряє наявність товарів і списує придбану кількість зі складу.
- Авторизований користувач може переглядати лише власні замовлення та їх склад.
- Каталог і сторінка товару працюють через `ListView` та `DetailView`. Створювати, редагувати й видаляти товари може staff-користувач. Маршрути керування доступні з профілю.

Оплата в навчальній версії фіксується як накладений платіж при отриманні. Банківські реквізити картки покупця не збираються, а реальний платіжний сервіс не підключений.

Для роботи сповіщень у Telegram використовується Telegram Bot API. Токен бота задається змінною `TELEGRAM_BOT_TOKEN`, а ім'я бота — `TELEGRAM_BOT_USERNAME` у `.env`. Посилання на Telegram-канал головної сторінки задається необов’язковою змінною `TELEGRAM_CHANNEL_URL`.
